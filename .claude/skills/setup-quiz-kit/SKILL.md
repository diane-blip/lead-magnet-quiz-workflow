# Setup Quiz Kit + D1

Automate **Kit** account setup and the **D1 analytics** database for quiz funnels generated by `/lead-magnet-quiz`.

> This skill provisions the client's **Kit** account (custom fields, tags, temperature sequences, seeded emails) and one Cloudflare **D1** analytics table, then deploys. It is not a Supabase database setup. Full reference: `agents/lead-magnet-agents/shared/kit-integration.md` and `agents/lead-magnet-agents/build-agent/references/cloudflare-kit-patterns.md`.

## Trigger

```
/setup-quiz-kit [business-name]
```

If no business name provided, list available funnels and ask which one to set up.

---

## Prerequisites

Before running this skill, the user must have:
1. The **client's own** Kit account (never SRC's / Diane's). If the client has no Kit account, creating one is part of onboarding. Firm rule: the funnel always lives in the client's Kit account so the client owns their list and the handoff is clean.
2. The Kit MCP connected for build-time setup (account-level connector in Diane's environment).
3. The client's **Kit v4 API key** ready (it becomes a deployed secret, `KIT_API_KEY`).
4. `wrangler` authenticated for the deploy (Cloudflare account access).

---

## Workflow

### Step 1: Locate the Quiz Funnel

1. If business name provided, construct path:
   ```
   output/[business-name]/
   ```

2. If no business name, list available funnels:
   ```bash
   ls output/
   ```
   Then ask user which one to set up.

3. Find the deploy folder with package.json (handles nested structure):
   ```bash
   find [output-folder] -name "package.json" -path "*/deploy/*" | head -1
   ```
   The folder containing this package.json is where we run commands.

### Step 2: Verify Quiz Funnel Exists

Check that required files exist:
- `package.json`
- `wrangler.jsonc`
- `architecture.md` (profiles, temperatures, diagnostic questions) in the client docs
- `email-sequences.csv` and `content-blocks.csv` in the client docs
- `d1/analytics-schema.sql` (the single D1 analytics table)

If any are missing, report error and exit.

### Step 3: Read the Funnel Definition

Read the source material the Kit setup is built from:
- `architecture.md` — profiles, temperatures, diagnostic questions (these define the custom fields, tags, and which answers drive the answer callbacks).
- `email-sequences.csv` — the email bodies to seed, with their day offsets (these become Kit sequence email delays).
- `content-blocks.csv` — profile blocks + answer callbacks. The deployed Worker resolves these at submit time into custom fields; Kit just merges them, so no resolution logic lives in Kit.

### Step 4: Collect the Kit API Key

Ask the user for the client's Kit v4 API key. Present this message:

```
I'll set up the client's Kit account and the analytics database for this funnel.

This always runs against the **client's own** Kit account, never SRC's. I'll use the connected Kit MCP to create the custom fields, tags, sequences, and seeded emails.

I need one value from you:

1. **KIT_API_KEY** — the client's Kit v4 API key.
   This gets stored as a deployed secret so the live site can register leads in the client's Kit account.
   Find it in the client's Kit account under Settings > Advanced > API.

(No Supabase, no database password, no Resend key needed anymore — Kit owns the list and the email.)

Please paste the Kit API key:
```

### Step 5: Build the Client's Kit Account (Kit MCP)

Using the Kit MCP, create everything build-time, once for this client. See `kit-integration.md` for the exact field/tag/sequence spec.

1. **Custom fields** (`bulk_create_custom_fields`):
   - `quiz_profile`, `quiz_temperature`, `quiz_score`
   - `profile_block`, `answer_callback_1`, `answer_callback_2`

2. **Tags**:
   - `quiz:profile:<profile-id>` — one per result profile from `architecture.md`
   - `quiz:temp:hot` / `quiz:temp:warm` / `quiz:temp:cold`
   (Prefix configurable via `KIT_TAG_PREFIX`.)

3. **Sequences** — the 3 temperature tracks plus Re-Engagement:
   - Cold Nurture → `KIT_SEQUENCE_COLD`
   - Warm Activation → `KIT_SEQUENCE_WARM`
   - Hot Path → `KIT_SEQUENCE_HOT`
   - Re-Engagement (runs at the tail of each track)
   Welcome content sits at the front of each track (or as a shared Welcome sequence that automates into the track).

4. **Seed the emails** from `email-sequences.csv`. Where a body contains `{{profile_block}}` / `{{answer_callback_N}}`, author the Kit email with Liquid merge tags:
   ```liquid
   {{ subscriber.custom_fields.profile_block }}
   {{ subscriber.custom_fields.answer_callback_1 }}
   ```
   Every email must read cleanly if a field is empty — keep the generic fallback sentence at each insert point. Day offsets from the CSV become Kit sequence email delays.

### Step 6: Emit the Tag / Sequence ID Map

Kit returns the IDs of the tags and sequences it just created. Write them into the deploy config so the runtime Worker can address them:

1. Into `wrangler.jsonc` vars: `KIT_SEQUENCE_HOT`, `KIT_SEQUENCE_WARM`, `KIT_SEQUENCE_COLD`, `KIT_TAG_PREFIX`, `DATA_RETENTION_ANALYTICS_DAYS`.
2. Into a generated `src/lib/kit-ids.ts` — the `TAG_IDS` name→id map the Worker's `kitTag` helper reads.

### Step 7: Create + Migrate the D1 Analytics Database

The only database in the stack is one Cloudflare D1 table for analytics. No leads table, no email queue — those live in Kit.

```bash
cd [deploy-folder]
npm install
wrangler d1 create [clientname]-quiz-analytics      # once; paste the returned id into wrangler.jsonc
wrangler d1 execute ANALYTICS_DB --file=./d1/analytics-schema.sql
```

### Step 8: Set Secrets and Deploy

```bash
wrangler secret put KIT_API_KEY        # the client's Kit v4 key from Step 4
wrangler secret put ADMIN_PASSWORD     # gate for /api/analytics-query and /admin
npm run build
wrangler deploy
```

### Step 9: Record the Deliverable

Per the Obsidian home-base rule, record the finished funnel deliverable in the vault at `clients/<client>/` (not Notion, not GitHub-only). Note the deployed URL, the Kit account it runs against, the created sequence/tag IDs, and the D1 database name.

### Step 10: Report Success

Output this summary:

```
✅ Kit + D1 setup complete!

**Created in the client's Kit account:**
- Custom fields: quiz_profile, quiz_temperature, quiz_score, profile_block, answer_callback_1, answer_callback_2
- Tags: quiz:profile:<id> (one per profile) + quiz:temp:hot/warm/cold
- Sequences: Cold Nurture, Warm Activation, Hot Path, Re-Engagement (emails seeded from email-sequences.csv with Liquid merge tags)

**Created in your site's hosting:**
- One D1 analytics table (analytics_events) — no PII; email and quiz answers live on the Kit subscriber record

**Deployed:**
- KIT_API_KEY and ADMIN_PASSWORD set as secrets
- Sequence + tag IDs written into the deploy config (wrangler.jsonc vars + src/lib/kit-ids.ts)
- Site built and deployed

**Test your quiz:**
- Visit [your-domain]/quiz
- Complete the quiz
- Confirm a subscriber appears in the client's Kit account with the custom fields set and the temperature sequence started
- Check the /admin dashboard

**Deliverable recorded at:** clients/<client>/
```

## Error Handling

### Quiz Funnel Not Found
```
❌ Quiz funnel "[name]" not found.

Available funnels:
- [list funnels]

Usage: /setup-quiz-kit [business-name]
```

### Missing Files
```
❌ Missing required files in deploy folder:
- [list missing files]

This quiz funnel may have been generated with an older version.
Please regenerate using /lead-magnet-quiz.
```

### Kit API / Auth Error
```
❌ Kit setup failed.

Check the Kit connection:
- Is the Kit MCP connected for build-time setup?
- Is the KIT_API_KEY the client's own v4 key (not SRC's)?
- Does the key have permission to create custom fields, tags, and sequences?

Error: [actual error message]
```

### Kit Objects Already Exist
```
⚠️ Some custom fields, tags, or sequences already exist in the client's Kit account.

Kit is idempotent by key/name for most objects — reuse the existing ones and capture
their IDs into the deploy config rather than creating duplicates. Only recreate an object
if it was created incorrectly. If you do recreate, delete the old one in the Kit web app
first, then re-run this skill.
```

### D1 Database Error
```
❌ D1 analytics setup failed.

Check the deploy:
- Is wrangler authenticated (Cloudflare account access)?
- Did you paste the id from `wrangler d1 create` into wrangler.jsonc?
- Does ./d1/analytics-schema.sql exist in the deploy folder?

Error: [actual error message]
```

---

## Notes

- This skill does NOT create the client's Kit account — the client must have one first (or set one up during onboarding). The funnel always runs against the client's own Kit account, never SRC's.
- The only database is one D1 analytics table. Leads and email both live in Kit. There is no leads table, no email queue, and no cron sending mail.
- The Kit API key is stored as a deployed secret (`wrangler secret put KIT_API_KEY`), not in a committed file.
- This is the Kit + D1 setup step, run after `/lead-magnet-quiz`.
